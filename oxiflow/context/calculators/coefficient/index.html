§Module context::calculators::coefficient

Coefficient fields c(x) and c(x, t) evaluated on the mesh nodes (DD-066, #182).

CoefficientField evaluates a user function on Mesh::coordinates(i) for every node i and publishes the result as a ScalarField under ContextVariable::Coefficient { name }. It is the space-dependent sibling of ExternalTabulated, which stays a function of time only and publishes a Scalar.

§Sharing without copy (DT-068)

The calculator overrides ContextCalculator::compute_shared, so the solver receives the field it keeps instead of a copy:

  • c(x) is evaluated once, at construction, and every evaluation gets the same allocation;
  • c(x, t) keeps its last time and value: evaluations at the same time (the stages of a step at one time, the n + 1 evaluations of a dense Jacobian) share one computation.

Both caches assume the mesh does not change after construction. This is an implementation detail, not a public contract: invalidation on a moving or adapted mesh is for v0.11.0 and later (DD-066).

The cache of c(x, t) is never locked while the field is computed. The solver may evaluate derivatives inside Rayon tasks (DT-069), and a worker waiting for its own parallel loop can run another such task: if that task blocked on a lock held by the same worker, it would never be released. Concurrent misses at the same time therefore compute the same field independently; the finite-difference Jacobians do not cause them, since they evaluate the unperturbed state before dispatching columns.

§Parallel dispatch (DA-048)

With the parallel feature, the nodes are evaluated through Rayon once the mesh has at least as many nodes as the calculator’s threshold, and each value is written directly into the output vector (no intermediate collection, see #144). The threshold governs c(x, t); c(x) is evaluated once, at construction, with the default threshold. Each node is evaluated by the same function with the same arguments in both modes, so the sequential and parallel fields are bit-for-bit identical.
