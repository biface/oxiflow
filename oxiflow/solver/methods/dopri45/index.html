§Module solver::methods::dopri45

Dormand-Prince DoPri45 — explicit, adaptive step, order 5 (local extrapolation) with embedded order-4 error estimate (issue #42).

§Algorithm

7-stage embedded Runge-Kutta pair. The FSAL (First Same As Last) property of the Dormand-Prince tableau means stage 7’s evaluation point is the 5th-order solution — no separate weighted sum needed to obtain it (see dopri45_stages below). The 4th-order solution is never computed explicitly either: only the difference b_i - b*_i is needed for the error estimate.

The coefficients are those of Dormand & Prince (1980). The tests check them against the Runge-Kutta order conditions (one condition per rooted tree, Butcher): the weights b satisfy all 17 conditions up to order 5, and the embedded weights b* = b - e satisfy the 8 conditions up to order 4 and miss order 5, as the lower-order member of an embedded pair should. The row sums sum_j a_ij = c_i are checked as well.

§Step-size control (DD-036)

Delegates entirely to StepSizeController for the accept/reject decision and the next dt — this file only supplies the error norm input (the RK4/5 difference) and the rejection retry loop. See super::step_control for the controller itself.

§Advective step limit (DA-073)

An advective term limits the step of an explicit method: with s the largest wave speed the model declares (PhysicalModel::max_wave_speed) and Δx the characteristic length of the mesh, the Courant number s·Δt/Δx must not exceed 1, a necessary condition shared by all the explicit integrators of the crate. At the start of each step the solver evaluates s on the state, with the first stage, and shortens a trial step above Δx / s to that value before computing the other stages, instead of failing as forward Euler and RK4 do with their fixed step. The first stage is then evaluated again, its context carrying the shortened step.

A shortened step is not a rejection: it is counted under the metadata key "solver.cfl_limited_steps", at most once per step, since a rejection only shortens the step further. A count close to "solver.accepted_steps" means that stability, not the tolerance, sets the step: an implicit integrator is then likely the better choice. The limit applies below dt_min too: dt_min bounds the steps the controller may choose to meet the tolerance, while the limit is a stability bound, and a positive one, so the run still advances. A model that declares no speed is not limited; the diffusive (Fourier) limit is never checked.

§State variants

Stage states and the error estimate are built with the crate’s linear combination of states, and the error norm reads every value of the state, so a VectorField (n nodes × d components) is advanced like a ScalarField: all components weigh the same in the RMS norm (#192). For a ScalarField, results are bit-identical to the former DVector arithmetic.

§Scope — Solver only, not SteppableSolver (see discussion)

Unlike BDF2 (DD-034), this solver does not implement SteppableSolver. BDF2’s gap (needing u^{n-1}) was orthogonal to dt itself; this solver’s defining feature is choosing its own dt across calls, which is in direct tension with MultiDomainOrchestrator’s v1 scope (DA-031: dt synchronised across domains). Making this orchestrator-compatible would mean re-opening the multirate question DA-031 already deferred — not a gap orthogonal to an existing limitation, but the same one. Revisit together if multirate coupling is ever tackled.

§Acceptance criteria mapping (#42)

  • Step-size control within rtol/atol: enforced by StepSizeController::accept.
  • dt_min guard -> OxiflowError::SolverDivergence: the rejection retry loop below bails out once the controller can no longer suggest a smaller dt.
  • Accepted/rejected counts in SimulationResult::metadata: keys "solver.accepted_steps" / "solver.rejected_steps", following the convention already documented on SimulationResult, plus "solver.cfl_limited_steps" for the steps shortened to the advective limit (see above).
  • Performance comparable to fixed-step RK4 on non-stiff problems: not benchmarked here (no compiler in this environment) — worth checking once this runs for real.
