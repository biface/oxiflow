§Module solver::methods::euler

Forward Euler integrator — explicit, 1st order (issues #33, #41).

§Algorithm

At each time step:

$$u^{n+1} = u^n + \Delta t \cdot f(u^n, \text{ctx}^n)$$

where $f = \text{compute_physics}(u, \text{ctx})$ is the time derivative returned by the physical model, evaluated on u after boundary conditions have been enforced (see super::evaluate_derivative).

§Scope

  • Single-domain scenarios only (n_domains() == 1). Multi-domain scenarios with CouplingOperator go through MultiDomainOrchestrator, which drives this solver per domain as a SteppableSolver (DA-031).
  • No spatial scheme inside the integrator (INV-2): the model computes du/dt from the field state and context, spatial operators included.
  • Boundary conditions ARE applied (since v0.2.0 / DA-008) — fixed in #41; the original J1 implementation predated BoundaryCondition and never called it, silently violating the contractual order documented in crate::solver.
  • StepControl::Fixed { dt } only — adaptive step control is DoPri45’s job (#42).

§Stability

An advective term limits the step of an explicit method: with s the largest wave speed the model declares (PhysicalModel::max_wave_speed) and Δx the characteristic length of the mesh, the Courant number must satisfy

$$C = \frac{s \cdot \Delta t}{\Delta x} \leq 1$$

SteppableSolver::step evaluates s on the state at the start of the step and fails with OxiflowError::PreconditionFailed (context "ForwardEulerSolver::step") before advancing when dt exceeds Δx / s, the message giving the Courant number and the limit (DA-073). The condition is necessary, not sufficient: forward Euler with a centred flux is unstable at any step in pure advection. A model that declares no speed is not checked; the diffusive (Fourier) limit is never checked.
