§Module solver::methods::implicit

Shared machinery for implicit (theta-method) integrators — DD-033 (#86).

BackwardEulerSolver (θ=1), CrankNicolsonSolver (θ=0.5) and BDF2Solver are thin wrappers around implicit_step_newton (DD-044, #111, #112) and, with the sparse feature, implicit_step_adaptive (DA-043). Each solver names its implicit equation with an ImplicitFormula — the theta method or BDF2 — and every formula runs the shared super::newton loop; the two paths differ only in the storage format of the linear system, dense or banded.

§Why one theta formula serves two methods

The generalised theta method is:

$$u^{n+1} = u^n + \Delta t\left[(1-\theta) f(u^n) + \theta f(u^{n+1})\right]$$

Linearising the residual $g(u) = u - u^n - \Delta t[(1-\theta)f(u^n) + \theta f(u)]$ at $u = u^n$ gives $g(u^n) = -\Delta t \cdot f(u^n)$ for any $\theta$ — the right-hand side of the linear correction doesn’t depend on θ at all. Only the system matrix does ($I - \theta \Delta t J_f$). One function, one parameter.

§Iterated Newton, single correction by default (DD-033, DD-044)

DD-033 (#86) started with exactly one Newton-style correction, with the Jacobian frozen at $u^n$ — exact when compute_physics is affine in u, a first-order approximation otherwise. DD-044 (#111) replaced it with the iterated super::newton loop, configured by the solver’s with_newton_convergence/with_jacobian_strategy/ with_max_newton_iterations builders. Their defaults (NewtonParams::default()) keep a single frozen-Jacobian correction, which reproduces the historical output exactly on affine problems (see super::newton’s own docs for why no special-casing is needed), and report OxiflowError::NewtonNotConverged rather than a first-order approximation on a nonlinear one.

The dense and the banded paths share the loop, the residual and the configuration, whatever the formula: the banded path assembles $\alpha I - c J_f$ in compressed columns from banded_finite_difference_jacobian and solves it with the solver’s SparseLinearSolver, nothing more.

§State variants

Newton and both finite-difference Jacobians work on the flat vector of unknowns given by StateLayout (super::state_layout): a ScalarField as is, a VectorField interleaved by node, so a VectorField state is advanced like a ScalarField (#192). The banded path therefore takes a half-bandwidth counted in flat unknowns, d·(s + 1) − 1 for d components and a stencil of half-width s.

§Boundary conditions × the perturbed Jacobian

finite_difference_jacobian perturbs each component of the state and re-evaluates evaluate_derivative, which re-applies boundary conditions on every call. A Dirichlet-constrained node will have its perturbation overwritten before compute_physics sees it — physically correct (a BC-constrained node isn’t a free unknown): the constrained node’s own column in the assembled Jacobian is exactly zero, while its row still reflects genuine physics-based coupling to unconstrained neighbours. Verified by tests::dirichlet_constrained_column_is_exactly_zero_row_keeps_real_coupling (#113) — previously documented as a known untested limitation (DD-033, #86, v0.4.0).

§Parallel assembly (DT-069)

With the parallel feature, both finite-difference Jacobians dispatch their independent evaluations through Rayon — one per column for the dense one, one per color for the banded one — once the system has at least as many unknowns as the solver’s dispatch threshold. Each Rayon job perturbs its own work state and writes its columns in place, in the final matrix. Every column is computed from the same operands with the same operations in both modes, so the sequential and parallel Jacobians are bit-for-bit identical. The threshold belongs to each implicit solver (JacobianDispatch); without the feature it does not exist and the assembly is sequential.
