§Module solver::parallel

Shared Rayon-dispatch-threshold mechanism (DD-014, DD-048) — a small, reusable building block for every site in the crate that decides, per element, whether to run a computation sequentially or through Rayon. Extracted after the same field/builder/guard triplet was written twice, verbatim, on FDGradientCalculator and FDLaplacianCalculator (DD-014, #51) — see DD-048 for the full rationale (architecture principles P1-P5) behind this module’s shape.

§What this is not

Not a trait imposed on ContextCalculator/DiscreteOperator/ FluxDivergenceOperator — DD-048 explicitly rejects that shape, mirroring the precedent already set twice (DD-012 amendment 2, DD-039 option A): forcing an orthogonal capability onto every implementer of a shared trait, when only some of them benefit from it. Each site that wants Rayon dispatch holds a [ParallelThreshold] field and reads it itself — a plain data-holding type, not a behavioural contract.

Entirely gated behind the parallel feature, at the module declaration itself (solver::mod) — mirrors solver::sparse/ solver::gpu’s own gating, not merely the items inside it.
