1//! # oxiflow
2//!
3//! Generic numerical engine for transport, reaction, and diffusion problems.
4//!
5//! ## The canonical form
6//!
7//! Every problem solved by oxiflow is expressed as a conservation law or field
8//! equation of the form:
9//!
10//! $$\frac{\partial u}{\partial t} + \nabla \cdot F(u, \nabla u) = S(u, \mathbf{x}, t)$$
11//!
12//! where:
13//!
14//! - **`u(x, t)`** — the primary field: concentration, temperature, velocity,
15//!   pressure, magnetic flux density, or any other quantity that evolves in
16//!   time and space.
17//! - **`F(u, ∇u)`** — the flux tensor, which may combine:
18//!   - *advective* flux `v·u` (transport by a flow field),
19//!   - *diffusive* flux `-D·∇u` (Fick, Fourier, Darcy),
20//!   - *dispersive* flux (higher-order spreading, e.g. in chromatography).
21//! - **`S(u, x, t)`** — source or reaction term: chemical reactions, heat
22//!   generation, gravity, electromagnetic forcing, adsorption isotherms.
23//!
24//! Second-order-in-time problems (`∂²u/∂t²`, structural dynamics, wave
25//! propagation) are reduced to this form by introducing `v = ∂u/∂t` as a
26//! second field component: the state `(u, v)` evolves as a first-order
27//! system. No dedicated second-order integrator (RKN, Newmark-β, HHT-α) is
28//! planned: order reduction is the retained approach ([DD-030](https://github.com/biface/oxiflow/issues/81)).
29//!
30//! ## Physical domains
31//!
32//! oxiflow covers any problem expressible as the canonical form above.
33//!
34//! | Domain | Primary field `u` | Reference example (J10) |
35//! |---|---|---|
36//! | Chromatographic transport | concentrations `cᵢ(z,t)` | `competitive_frontal_analysis` ([#174](https://github.com/biface/oxiflow/issues/174)) |
37//! | Transient heat conduction | temperature `T(x,t)` | `heat_transfer_1d` ([#175](https://github.com/biface/oxiflow/issues/175)) |
38//! | Reaction-diffusion | species `(u,v)` | `gray_scott_1d` ([#176](https://github.com/biface/oxiflow/issues/176)) |
39//! | Viscous flow (Burgers) | velocity `u(x,t)` | `burgers_boundary_layer` ([#177](https://github.com/biface/oxiflow/issues/177)) |
40//! | Porous media consolidation (Terzaghi) | excess pore pressure `u(z,t)` | `consolidation_1d` ([#178](https://github.com/biface/oxiflow/issues/178)) |
41//! | Resistive magnetic diffusion | flux density `B` | `magnetic_diffusion_1d` (prototype, [#179](https://github.com/biface/oxiflow/issues/179)) |
42//! | Shallow water (Saint-Venant) | depth `h`, momentum `hv` | `lahar_lake_wave` ([#180](https://github.com/biface/oxiflow/issues/180)) |
43//!
44//! Other problems of the canonical form are candidates without a reference
45//! example yet: Darcy flow (water content `θ`), Nernst-Planck (ionic
46//! concentrations `cᵢ`), structural dynamics (displacement `u`, velocity `v`,
47//! through order reduction, [DD-030](https://github.com/biface/oxiflow/issues/81)).
48//!
49//! For full equations, physical derivations, and numerical details,
50//! see the **[project wiki](https://github.com/biface/oxiflow/wiki)**.
51//!
52//! ## Numerical structure
53//!
54//! In each domain above, `u` changes physical meaning, but the engine abstraction
55//! is identical:
56//!
57//! | Physical concept | Engine abstraction |
58//! |---|---|
59//! | Field `u(x,t)` | `ContextValue::ScalarField` / `VectorField` |
60//! | Spatial domain | `Mesh` (INV-1) — `UniformGrid1D` (J1), FEM (J11) |
61//! | Flux F, source S | `PhysicalModel::compute_physics(u, ctx)` |
62//! | Auxiliary quantities | `ComputeContext` ← `ContextCalculator` chain |
63//! | Time integration | `Solver` — Euler, RK4, … (J4) |
64//! | Boundary conditions | `BoundaryCondition: RequiresContext` (J2) |
65//! | Multi-domain coupling | `CouplingOperator` (INV-3, J3) |
66//! | Spatial operators | `DiscreteOperator<M: Mesh>` (INV-2, J5) |
67//!
68//! ## Architecture — WHAT / HOW separation
69//!
70//! Three strictly separated responsibilities:
71//!
72//! | Type | Pole | Role |
73//! |---|---|---|
74//! | [`solver::Scenario`] | WHAT | Declares the problem: model, mesh, domains, BCs |
75//! | [`solver::SolverConfiguration`] | HOW | Configures solving: integrator, step control, calculators |
76//! | [`solver::Solver`] | Execution | Orchestrates the time integration loop |
77//!
78//! The engine enforces a **contractual execution order** at each time step:
79//!
80//! 1. Context calculators populate [`context::ComputeContext`]
81//! 2. Boundary conditions are applied to the current state (J2)
82//! 3. [`model::PhysicalModel::compute_physics`] computes `du/dt`
83//! 4. The integrator advances the state by `dt`
84//!
85//! ## Modules
86//!
87//! - [`context`]   — [`context::ContextVariable`], [`context::ContextValue`],
88//!   [`context::OxiflowError`], [`context::ComputeContext`], [`context::ContextCalculator`]
89//! - [`mesh`]      — [`mesh::Mesh`] trait (INV-1) and [`mesh::UniformGrid1D`] (J1)
90//! - [`model`]     — [`model::RequiresContext`] and [`model::PhysicalModel`]
91//! - [`solver`]    — [`solver::Scenario`], [`solver::SolverConfiguration`],
92//!   [`solver::Solver`], [`solver::SimulationResult`]
93//! - [`boundary`]  — `BoundaryCondition` trait (J2)
94//! - [`operators`] — `DiscreteOperator<M: Mesh>` (INV-2, J5)
95//! - [`coupling`]  — `CouplingOperator` (INV-3, J3)
96//!
97//! ## FEM invariants — forward compatibility
98//!
99//! All abstractions from v0.1 are designed to extend naturally to FEM from
100//! v0.11.0 (J11) without any breaking change on existing code.
101//!
102//! | Invariant | Guarantee | Active from |
103//! |---|---|---|
104//! | INV-1 | No `dx`/`nx` in public API — all spatial access via [`mesh::Mesh`] | v0.1.0 |
105//! | INV-2 | Integrators decoupled from spatial scheme via `DiscreteOperator<M>` | v0.5.0 |
106//! | INV-3 | Inter-domain coupling only via `CouplingOperator` | v0.3.0 |
107//! | INV-4 | All public traits object-safe — external crates can implement them | v0.30.0 ([DA-017](https://github.com/biface/oxiflow/issues/17)) |
108//!
109//! ## Getting started (J1)
110//!
111//! ```rust
112//! use nalgebra::DVector;
113//! use oxiflow::{
114//!     context::{ComputeContext, ContextValue, ContextVariable, OxiflowError},
115//!     mesh::{Mesh, UniformGrid1D},
116//!     model::{PhysicalModel, RequiresContext},
117//!     solver::{methods::ForwardEulerSolver, IntegratorKind, Scenario, Solver,
118//!              SolverConfiguration, StepControl, TimeConfiguration},
119//! };
120//!
121//! // 1. Declare the physical model: du/dt = -u
122//! struct MyModel;
123//! impl RequiresContext for MyModel {
124//!     fn required_variables(&self) -> Vec<ContextVariable> {
125//!         vec![ContextVariable::Time]
126//!     }
127//! }
128//! impl PhysicalModel for MyModel {
129//!     fn compute_physics(
130//!         &self,
131//!         state: &ContextValue,
132//!         _ctx: &ComputeContext,
133//!     ) -> Result<ContextValue, OxiflowError> {
134//!         Ok(ContextValue::ScalarField(-state.as_scalar_field()?.clone()))
135//!     }
136//!     fn initial_state(&self, mesh: &dyn Mesh) -> ContextValue {
137//!         ContextValue::ScalarField(DVector::from_element(mesh.n_dof(), 1.0))
138//!     }
139//!     fn name(&self) -> &str {
140//!         "my_model"
141//!     }
142//! }
143//!
144//! // 2. Declare the problem (WHAT)
145//! let mesh = UniformGrid1D::new(100, 0.0, 1.0)?;
146//! let scenario = Scenario::single(Box::new(MyModel), Box::new(mesh));
147//!
148//! // 3. Configure solving (HOW)
149//! let config = SolverConfiguration::new(
150//!     TimeConfiguration::new(1.0, StepControl::Fixed { dt: 0.1 }),
151//!     IntegratorKind::Euler,
152//! );
153//!
154//! // 4. Solve
155//! let result = ForwardEulerSolver.solve(&scenario, &config)?;
156//! assert_eq!(result.states.len(), result.times.len());
157//! # Ok::<(), OxiflowError>(())
158//! ```
