1//! # Module `solver::parallel`
2//!
3//! Shared Rayon-dispatch-threshold mechanism ([DT-014](https://github.com/biface/oxiflow/issues/14), [DA-048](https://github.com/biface/oxiflow/issues/140)) — a small,
4//! reusable building block for every site in the crate that decides, per
5//! element, whether to run a computation sequentially or through Rayon.
6//! Extracted after the same field/builder/guard triplet was written
7//! twice, verbatim, on `FDGradientCalculator` and `FDLaplacianCalculator`
8//! ([DT-014](https://github.com/biface/oxiflow/issues/14), [#51](https://github.com/biface/oxiflow/issues/51)) — see [DA-048](https://github.com/biface/oxiflow/issues/140) for the full rationale (architecture
9//! principles P1-P5) behind this module's shape.
10//!
11//! ## What this is not
12//!
13//! Not a trait imposed on `ContextCalculator`/`DiscreteOperator`/
14//! `FluxDivergenceOperator` — [DA-048](https://github.com/biface/oxiflow/issues/140) explicitly rejects that shape,
15//! mirroring the precedent already set twice ([DA-012](https://github.com/biface/oxiflow/issues/12) amendment 2, [DA-039](https://github.com/biface/oxiflow/issues/95)
16//! option A): forcing an orthogonal capability onto every implementer of
17//! a shared trait, when only some of them benefit from it. Each site that
18//! wants Rayon dispatch holds a `ParallelThreshold` field and reads it
19//! itself — a plain data-holding type, not a behavioural contract.
20//!
21//! Entirely gated behind the `parallel` feature, at the module
22//! declaration itself (`solver::mod`) — mirrors `solver::sparse`/
23//! `solver::gpu`'s own gating, not merely the items inside it.
24//!
25//! ## Sizing a threshold
26//!
27//! A dispatch pays once the work it splits outweighs the cost of handing
28//! it to the Rayon pool. That work reads best as the sequential time of
29//! one call of the dispatched loop, the number of items times the cost of
30//! one item, rather than as a node count, which means nothing without the
31//! cost of a node. On the design machine (Intel Core i5-1335U, 12 Rayon
32//! threads), the reference run of the `oxiflow_parallel` benchmarks for
33//! v0.10.0 ([#214](https://github.com/biface/oxiflow/issues/214)) puts the crossover early for loops limited by
34//! arithmetic: parallel loses while one call lasts 10 to 30 µs
35//! sequentially, and wins from about 100 µs for heavy items (a Langmuir
36//! row, a lahar source node) and 300 µs for the lightest (a closed-form
37//! coefficient), that is from about 10³ items at 100 ns each or 10⁵ items
38//! at 3 ns each. Loops limited by memory bandwidth cross much later:
39//! between 0.4 and 4 ms of sequential work for the lahar flux, around
40//! 30 ms for the FD Laplacian.
41//!
42//! Two effects move the crossover in a full run. Inside a time step, a
43//! dispatch sits between sequential phases and costs more than in a
44//! back-to-back benchmark loop. Under `MultiDomainOrchestrator`, the
45//! dispatch inside each domain competes with the dispatch across domains.
46//! Every default in the crate is therefore an indicative starting point:
47//! measure the target workload with [`calibrate_parallel_threshold`] or the
48//! benchmarks under `benches/`, then set the threshold of each site. The
49//! abaques of the reference run, with the charts and tables of every site,
50//! are on the wiki: [Dispatch abaques](https://github.com/biface/oxiflow/wiki/Dispatch-abaques).
51
52use std::sync::atomic::{AtomicUsize, Ordering};
53
54/// Per-instance Rayon dispatch threshold.
55///
56/// Stores `0` internally to mean "no override" — `0` is otherwise
57/// forbidden by [`Self::set`], so it is free to reuse as a sentinel
58/// without an `Option` (which would block mutation through `&self`
59/// without extra indirection). [`Self::get`] resolves the sentinel to a
60/// caller-supplied default rather than materializing that default at
61/// construction — one authoritative default, consulted on demand, rather
62/// than copied into every instance ([DA-048](https://github.com/biface/oxiflow/issues/140); closer to chrom-rs's single
63/// process-wide default than to a per-instance constant).
64///
65/// Deliberately per-instance, not a shared `static` (chrom-rs's own
66/// design) — `MultiDomainOrchestrator` ([DA-031](https://github.com/biface/oxiflow/issues/82)) can run several domains,
67/// each with its own solver, in the same process; a single global would
68/// force them to share one setting, with a "last writer wins" race
69/// between domains adjusting it independently. Reconfigurable at runtime
70/// through `&self` via [`Self::set`] — no rebuild required, and no
71/// cross-instance leakage to guard against (unlike chrom-rs's
72/// `ThresholdGuard`, needed only because its threshold is global).
73#[derive(Debug, Default)]
74pub(crate) struct ParallelThreshold(AtomicUsize);
75
76impl ParallelThreshold {
77    /// Creates a threshold with no override — [`Self::get`] reports the
78    /// caller-supplied default until [`Self::set`] is called.
79    pub(crate) fn unset() -> Self {
80        Self(AtomicUsize::new(0))
81    }
82
83    /// Overrides the threshold.
84    ///
85    /// # Panics
86    ///
87    /// Panics when `threshold == 0` — reserved as the "unset" sentinel
88    /// (see the type's own docs), and not a value any real workload
89    /// should want anyway: it would force parallel dispatch on every
90    /// non-empty input, never the intended behaviour (mirrors chrom-rs's
91    /// own `set_parallel_threshold` guard). No other value is validated
92    /// — [DA-048](https://github.com/biface/oxiflow/issues/140) deliberately leaves "how low is too low" to the caller's
93    /// own measurement (see [`calibrate_parallel_threshold`]), consistent
94    /// with `sparse_threshold`/`jacobian_bandwidth` ([DA-043](https://github.com/biface/oxiflow/issues/103)), which
95    /// validate nothing at all: there is no threshold floor that is
96    /// universally sensible across workloads (chrom-rs's 999 is nearly a
97    /// total loss for the FD stencils [DT-014](https://github.com/biface/oxiflow/issues/14) calibrated 49999 against).
98    pub(crate) fn set(&self, threshold: usize) {
99        assert!(threshold > 0, "parallel threshold must be at least 1");
100        self.0.store(threshold, Ordering::Relaxed);
101    }
102
103    /// Returns the configured override, or `default` if none was set.
104    pub(crate) fn get(&self, default: usize) -> usize {
105        match self.0.load(Ordering::Relaxed) {
106            0 => default,
107            configured => configured,
108        }
109    }
110}
111
112/// Empirically measures the sequential/parallel crossover point for a
113/// given per-element workload, on the machine actually running the code
114/// — rather than assuming a number calibrated for a different workload
115/// or a different machine ([DA-048](https://github.com/biface/oxiflow/issues/140)).
116///
117/// Tries each of `candidate_sizes`, in order, timing a sequential loop
118/// and a Rayon `into_par_iter` dispatch of `work` over `0..n` elements;
119/// returns the first `n` where the parallel run was faster. Returns the
120/// largest candidate if none crossed over (a conservative "parallel
121/// never won at any size tried" outcome, not a panic), or `0` if
122/// `candidate_sizes` is empty.
123///
124/// `work` should be representative of the real per-element cost it will
125/// be used to threshold for — measuring a cheap placeholder closure and
126/// applying the result to a heavier one (or vice versa) defeats the
127/// purpose. Feeds [#53](https://github.com/biface/oxiflow/issues/53) (the Criterion benchmark suite) rather than
128/// duplicating its own crossover measurement.
129///
130/// # Examples
131///
132/// ```rust
133/// use oxiflow::solver::parallel::calibrate_parallel_threshold;
134///
135/// let threshold = calibrate_parallel_threshold(
136///     |i| {
137///         let _ = (i as f64).sqrt();
138///     },
139///     &[100, 1_000, 10_000, 100_000],
140/// );
141/// assert!(threshold > 0);
142/// ```
143pub fn calibrate_parallel_threshold<F>(work: F, candidate_sizes: &[usize]) -> usize
144where
145    F: Fn(usize) + Sync,
146{
147    use rayon::prelude::*;
148    use std::time::Instant;
149
150    for &n in candidate_sizes {
151        let seq_start = Instant::now();
152        for i in 0..n {
153            work(i);
154        }
155        let seq_elapsed = seq_start.elapsed();
156
157        let par_start = Instant::now();
158        (0..n).into_par_iter().for_each(&work);
159        let par_elapsed = par_start.elapsed();
160
161        if par_elapsed < seq_elapsed {
162            return n;
163        }
164    }
165
166    candidate_sizes.iter().copied().max().unwrap_or(0)
167}

171#[cfg(test)]
172mod tests {
173    use super::*;
174
175    // ── ParallelThreshold ──────────────────────────────────────────────────────
176
177    #[test]
178    fn unset_reports_the_supplied_default() {
179        let t = ParallelThreshold::unset();
180        assert_eq!(t.get(12345), 12345);
181    }
182
183    #[test]
184    fn set_overrides_the_default() {
185        let t = ParallelThreshold::unset();
186        t.set(42);
187        assert_eq!(t.get(12345), 42);
188    }
189
190    #[test]
191    #[should_panic(expected = "parallel threshold must be at least 1")]
192    fn set_rejects_zero() {
193        ParallelThreshold::unset().set(0);
194    }
195
196    #[test]
197    fn set_is_visible_through_shared_reference() {
198        let t = ParallelThreshold::unset();
199        let t_ref = &t;
200        t_ref.set(7);
201        assert_eq!(t.get(0), 7);
202    }
203
204    // ── calibrate_parallel_threshold ───────────────────────────────────────────
205    //
206    // No assertion depends on *which* candidate wins — that's a timing
207    // outcome, and asserting a specific crossover would make this test
208    // flaky under CI load. Only the contract (returns a candidate, or 0
209    // on empty input) is checked.
210
211    #[test]
212    fn calibrate_returns_one_of_the_candidates() {
213        let candidates = [10, 100, 1_000];
214        let threshold = calibrate_parallel_threshold(
215            |i| {
216                std::hint::black_box(i);
217            },
218            &candidates,
219        );
220        assert!(candidates.contains(&threshold));
221    }
222
223    #[test]
224    fn calibrate_on_empty_candidates_returns_zero() {
225        let threshold = calibrate_parallel_threshold(
226            |i: usize| {
227                std::hint::black_box(i);
228            },
229            &[],
230        );
231        assert_eq!(threshold, 0);
232    }
233}
